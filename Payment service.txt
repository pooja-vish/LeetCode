The system follows a microservices architecture. Requests first go through an API Gateway for authentication and routing. The Payment Service validates the request and creates a transaction with a PENDING status. It then publishes an event to Kafka. The Wallet Service consumes the event and performs debit/credit operations. Based on the result, the payment status is updated to SUCCESS or FAILED. Notification and Audit services consume events independently, making the system scalable and loosely coupled. Used PostgreSQL for persistence, Kafka for asynchronous communication, Redis for caching, and implemented idempotency keys to prevent duplicate payments.
